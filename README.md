# AppVault для Windows

Архив iOS-приложений и установка их на iPhone с компьютера на Windows — в том числе тех, что пропали
из App Store. Порт [AppVault для macOS](../../mac/AppVault) на Flutter: та же библиотека IPA, скачивание
своих покупок и их старых версий, переподпись своим сертификатом и установка по кабелю или Wi‑Fi.

## Что можно поставить и как

| Тип IPA | Как ставится | Ограничения |
|---|---|---|
| **App Store · FairPlay** — бинарник зашифрован | как есть: подпись Apple не истекает | на iPhone должен быть вход в App Store с тем Apple ID, которым приложение получено |
| **Без шифрования** — open source, свои сборки | переподпись вашим сертификатом | устройство должно быть в профиле; с платным аккаунтом подпись до года |

Откуда брать сборки App Store:

- **Мои покупки** — все приложения, когда-либо полученные вашим Apple ID, включая снятые с продажи.
- **По ID или ссылке** — числовой ID, ссылка apps.apple.com или bundle ID (числовой ID найдётся в покупках).
- **Старые версии** — кнопка «Версии»: все версии, которые хранит Apple.
- **С iPhone** — правый клик по приложению на вкладке «Устройства» → «Скачать в библиотеку»:
  скачивается ровно та версия, что установлена.
- **Найти на диске** — медиатека iTunes, iMazing, 3uTools, «Загрузки» и свои папки.

## Чем отличается от версии для Mac

- **Нет ловушки Apple Configurator** — Configurator есть только на Mac.
- **Переподпись — через [rcodesign](https://github.com/indygreg/apple-platform-rs)** вместо `codesign`.
  Права для каждого расширения задаются отдельно, как на Mac.
- **Сертификат — файл .p12.** Связки ключей нет: .p12 копируется в папку данных, пароль к нему хранится
  под DPAPI (расшифровать может только эта учётная запись Windows).
- **Профили Xcode недоступны** — добавляйте .mobileprovision вручную (developer.apple.com → Profiles)
  или включите режим App Store Connect API: AppVault сам регистрирует устройство и выпускает профили.

## Установка

Windows 10 1809+ или Windows 11, процессор Intel/AMD x64.

1. Скачайте **`AppVault-Setup.exe`** из раздела **Releases** репозитория, если опубликован релиз.
   Для сборки без релиза: **Actions → windows → успешный запуск → Artifacts → AppVault-windows**;
   распакуйте скачанный архив артефакта и запустите `AppVault-Setup.exe`.
2. Пройдите установку. AppVault устанавливается для текущего пользователя без прав администратора,
   создаёт ярлык в меню «Пуск» и, по выбору, на рабочем столе. Утилиты и библиотеки Visual C++ уже внутри:
   Flutter, Visual Studio, Homebrew и ручная загрузка утилит на компьютере пользователя не нужны.
3. Для iPhone установите **«Устройства Apple»** из Microsoft Store (или iTunes), подключите iPhone,
   разблокируйте его и подтвердите «Доверять этому компьютеру».

Повторный запуск установщика обновляет AppVault. Библиотека, сертификаты и настройки хранятся отдельно
от программы и сохраняются при обновлении и удалении. Удаление: «Параметры Windows → Приложения → AppVault».
Вместо установки можно распаковать `AppVault-windows.zip` и запустить `AppVault.exe` из него;
папки `data`, `tools` и DLL должны оставаться рядом с EXE.

### Утилиты при разработке

1. **«Устройства Apple»** из Microsoft Store (или iTunes) — ставит службу Apple Mobile Device, без неё
   Windows не видит iPhone. Для работы по Wi‑Fi один раз включите там «Показывать этот iPhone при подключении к Wi‑Fi».
2. **Утилиты**: `powershell -ExecutionPolicy Bypass -File scripts\fetch_tools.ps1` — скачивает и проверяет по SHA-256:
   - `ipatool` 2.7.0 — вход в App Store, покупки, версии, скачивание (неофициальный API App Store — это нарушает
     правила Apple, хотя для своих покупок работает);
   - `ideviceinstaller`, `idevice_id`, `ideviceinfo`, `idevicedevmodectl` — сборка libimobiledevice для Windows;
   - `rcodesign` 0.29.0 — переподпись.

   AppVault ищет утилиты в папке из настроек, в `tools` рядом с `AppVault.exe`, в `%LOCALAPPDATA%\AppVault\tools`
   (туда их кладёт скрипт) и в PATH.

## Подпись

- **.p12**: на Mac «Связка ключей» → «Мои сертификаты» → Apple Development → «Экспортировать…» с паролем;
  на Windows — вкладка «Подпись» → «Добавить .p12».
- **Свои профили**: для любых приложений нужен профиль iOS App Development с App ID «*», вашим сертификатом
  и устройством. Bundle ID остаётся исходным.
- **App Store Connect API**: ключ .p8 (App Store Connect → Users and Access → Integrations, роль Developer или Admin).
  Bundle ID получает суффикс команды — чужой идентификатор в своей команде не зарегистрировать.

Права исходного приложения сохраняются, если профиль их разрешает; остальные отбрасываются и перечисляются
в журнале задачи. Расширения можно убрать при переподписи, приложение для часов убирается по умолчанию.

## Сборка

```powershell
winget install --id JRSoftware.InnoSetup --exact
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

На машине сборки нужны Windows x64, Flutter 3.38.5, Visual Studio 2022 с «Разработкой классических
приложений на C++» (включая Windows SDK) и Inno Setup 6.3+. Версия берётся из `pubspec.yaml`.
Если `ISCC.exe` установлен в нестандартную папку, передайте `-IsccPath 'C:\...\ISCC.exe'`.

Результат в `dist`:

- **`AppVault-Setup.exe`** — установщик с русским и английским интерфейсом;
- `AppVault-windows.zip` — переносимая версия;
- `SHA256SUMS.txt` — контрольные суммы обоих файлов.

Загрузки утилит проверяются по SHA-256 и кэшируются в `build\tool-downloads`. В пакет включаются
все DLL Flutter и утилит, а также библиотеки Visual C++ из `VC\Redist\MSVC` установленной Visual Studio.
Скрипт проверяет наличие файлов и поддержку нужных команд настоящими утилитами.

Без Windows-машины используйте `.github/workflows/windows.yml`: workflow запускает анализатор,
тесты (включая DPAPI и конвейер переподписи), собирает установщик и ZIP, проверяет импорт `.p12`
и подпись IPA настоящим `rcodesign`, затем проверяет установку, появление окна, обновление и удаление.
Готовые файлы доступны в артефакте **AppVault-windows**. При публикации GitHub Release этот же workflow
собирает код релиза и прикрепляет файлы к нему для прямого скачивания. Изменения workflow должны быть
в основной ветке репозитория. Сборка Windows EXE на macOS через `flutter build windows` не поддерживается.

Проверка установщика вручную в чистой учётной записи Windows:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\test_installer.ps1
```

Проверка установки не обращается к Apple ID и не устанавливает приложения на iPhone.
Для проверки скачивания покупок и реальной установки на устройство нужны ваш Apple ID и iPhone.

## Разработка

Ядро (`lib/core`) не зависит от Windows, поэтому тесты и проверка на реальных устройствах идут и на Mac:

```bash
flutter test                 # plist, zip, Mach-O, CgBI, IPA, профили, права, конвейер переподписи, интерфейс
dart run tool/smoke.dart     # утилиты, устройства, вход в App Store — только чтение
```

`test/ipa_test.dart` сверяет разбор IPA с библиотекой Mac-версии, если она есть на этой машине.
Тесты с настоящим комплектом запускаются отдельно после сборки:

```powershell
$env:APPVAULT_TEST_TOOLS = (Resolve-Path 'build\windows\x64\runner\Release\tools').Path
flutter test test/toolchain_test.dart
```

## Где лежат данные

`%LOCALAPPDATA%\AppVault\`:

- `Library\` — по папке на IPA и `index.json`;
- `Profiles\` — добавленные профили, `Identities\` — сертификаты .p12;
- `Secrets\` — пароли под DPAPI: к .p12, ключ App Store Connect и пароль к хранилищу токена ipatool;
- `settings.json` — настройки.

Токен App Store хранит сам ipatool в `%USERPROFILE%\.ipatool`, в файле, зашифрованном паролем, который AppVault
создаёт при первом запуске. Пароль Apple ID не сохраняется.
